## 二、需求与实现范围

本次程序实现围绕以下闭环：

**发布信息 → 浏览或搜索 → 查看详情 → 联系发布者 → 更新状态**

已实现功能：

1. 浏览校园失物和招领信息。
2. 发布寻物信息或招领信息。
3. 按物品名称、地点或描述搜索。
4. 按类型、分类、地点筛选。
5. 查看物品详情和联系方式。
6. 一键复制联系方式。
7. 在“我的发布”中修改状态。
8. 表单校验、空结果提示、图片预览和响应式布局。

没有加入实名认证、即时聊天和地图定位，保持流程简单。

## 三、解题思路与代码设计

项目分为界面层、逻辑层和数据层。`index.html` 提供页面结构，`src/app.js` 处理 DOM、事件和 localStorage，`src/store.js` 负责校验、搜索和状态规则，`tests/store.test.js` 独立测试数据逻辑。逻辑层不依赖 DOM，因此可以在 Node.js 中直接运行测试。

![核心业务流程](https://raw.githubusercontent.com/Feion-Chen/102402118-102402117/main/docs/images/user-flow.png)

搜索实现会把物品名称、分类、地点和描述合并为搜索文本，支持多个关键词跨字段匹配。核心代码：

```javascript
const query = normalizeText(filters.query);
if (query) {
  const haystack = normalizeText([
    item.title,
    item.category,
    item.location,
    item.description,
  ].join(' '));
  const tokens = String(filters.query).trim().toLowerCase().split(/\s+/);
  if (!tokens.every((token) => haystack.includes(normalizeText(token)))) {
    return false;
  }
}
```

状态转换不直接在界面中任意修改，而是由配置约束。寻物信息只能在“寻找中”和“已找到”之间切换，招领信息只能在“待认领”和“已归还”之间切换：

```javascript
const STATUS_OPTIONS = {
  lost: ['searching', 'found'],
  found: ['holding', 'returned'],
};

updateStatus(id, status) {
  const item = this.getById(id);
  if (!STATUS_OPTIONS[item.type].includes(status)) {
    throw new Error('该状态不适合当前信息类型');
  }
  item.status = status;
  item.updatedAt = new Date().toISOString();
  return item;
}
```

数据使用 localStorage 保存，刷新或重新打开页面后仍能保留。图片通过 FileReader 转为 Data URL 后随信息一起保存在本机，不需要上传服务器。

## 四、附加特点

1. 分类与地点双重筛选，方便缩小搜索范围。
2. 一键复制联系方式，减少手工抄写。
3. 发布成功直接打开详情页，方便核对内容。
4. 图片大小限制为 2 MB，并支持移除预览。
5. 空结果状态提供“清除筛选”按钮。
6. 逻辑层与界面层分离，后续可以在不修改页面的情况下替换数据存储方式。

## 七、遇到的问题与解决

问题一：最初使用 ES Module 时，直接双击 HTML 可能被 Chrome 的本地文件策略拦截。解决方法是改用普通脚本并通过全局对象连接 `store.js` 和 `app.js`，保证无需服务器也能运行。

问题二：文件直接打开时，部分浏览器不允许访问 localStorage。代码对此做了容错处理，读取失败时使用示例数据，保存失败时提示但仍保留当前页面数据。

问题三：寻物和招领的状态含义不同。解决方法是使用状态配置表限制可选状态，并在“我的发布”中只显示合法的下一步操作。
